\chapter{Solution Approach}\label{chapter:solution-approach}

This chapter presents a framework for fusing a pretrained calibration network with a self-supervised pose estimator, introducing multi-frame calibration consistency through a learned feature aggregation module. The framework is first described in generic terms (Section~\ref{sec:architecture}), then instantiated with specific pretrained models (Section~\ref{sec:instantiation}), and finally the training procedure is detailed (Section~\ref{sec:training}).


% ============================================================================
\section{Architecture}\label{sec:architecture}
% ============================================================================

The proposed system consists of two branches that share the same input video frames (Figure~\ref{fig:pipeline-overview}):

\begin{itemize}
    \item A \textbf{calibration branch} that processes multiple frames through a pretrained calibration backbone, aggregates features via the Multi-Frame Calibration Transformer (MCT), and decodes to intrinsics $\mathbf{K}$.
    \item A \textbf{pose branch} that processes the same frames through a pretrained pose backbone with precomputed depth and flow, and predicts relative poses $(R, \mathbf{t})$ conditioned on $\mathbf{K}$.
\end{itemize}

The calibration branch (bottom) processes $N$ frames through a frozen calibration backbone, aggregates features via the MCT, and decodes to intrinsics $\mathbf{K}$. The pose branch (top) processes the same frames through a frozen pose backbone with precomputed depth and flow, and predicts relative poses conditioned on $\mathbf{K}$ via a focal embedding. Blocks marked \textsc{new} are our additions; all other components are frozen pretrained models.}

\end{figure}

\subsection{Calibration Branch}\label{sec:calib-branch-generic}

The calibration branch requires a pretrained network that extracts multi-scale spatial features from images and decodes them to camera intrinsics. The MCT is inserted between the frozen feature extractor and the frozen decoder:

\begin{enumerate}
    \item \textbf{Per-frame feature extraction.} Each of the $N$ input frames is independently processed by a frozen backbone, producing multi-scale spatial features at $S$ resolutions:
    \begin{equation}
        \mathbf{F}_i^{(s)} \in \mathbb{R}^{C \times h_s \times w_s}, \quad s \in \{1,\ldots,S\}, \quad i \in \{1,\ldots,N\}
    \end{equation}

    \item \textbf{Multi-Frame Calibration Transformer (MCT).} For each scale independently, features from all $N$ frames are reshaped to $(h \cdot w) \times N \times C$, treating each spatial position as a separate sequence of $N$ frame tokens. Two layers of multi-head self-attention allow each position to exchange information across frames. The attended features are then mean-pooled across the frame dimension:
    \begin{equation}
        \mathbf{F}_{\text{agg}}^{(s)} = \frac{1}{N} \sum_{i=1}^{N} \text{Attention}(\mathbf{F}_1^{(s)}, \ldots, \mathbf{F}_N^{(s)})_i
    \end{equation}
    The same transformer weights are shared across all scales. Attention operates only across the \emph{frame} dimension---spatial positions are independent batch items, so there is no spatial attention. The output has the same shape as a single-frame feature map, allowing the downstream decoder to be used without modification.

    \item \textbf{Decoding and calibration fitting.} The aggregated features pass through the frozen decoder to produce a dense geometric representation (e.g., per-pixel ray directions), from which camera intrinsics $(f_x, f_y, c_x, c_y)$ are recovered.
\end{enumerate}

\textbf{A key design choice is to aggregate at the feature level rather than at the scalar output level.} Averaging final predictions discards the rich spatial structure in the backbone's intermediate representations; the MCT preserves this geometric information by operating before decoding. The MCT is architecture-agnostic: it can be inserted between any backbone and decoder that share compatible multi-scale spatial feature maps.

\subsection{Pose Branch}\label{sec:pose-branch-generic}

The pose branch requires a self-supervised pose estimator that predicts relative camera motion from video frames. The framework imposes two requirements:

\begin{enumerate}
    \item \textbf{Calibration conditioning.} The pose branch must accept a calibration embedding as an additional input, so that pose predictions are conditioned on the intrinsics produced by the calibration branch. Concretely, the predicted focal length is converted to an embedding vector via harmonic positional encoding and concatenated with the pose features before the final prediction head.

    \item \textbf{Precomputed geometric priors.} The pose backbone must have access to precomputed depth and optical flow predictions (from frozen helper networks), which serve both as input features to the backbone and as the basis for the self-supervised training signal (flow reprojection loss).
\end{enumerate}

The pose backbone itself remains frozen; only lightweight prediction heads (the pose neck and pose head) are trainable. \textbf{This ensures that the large pretrained representations are preserved while only the fusion interface is learned.}

\subsection{Calibration--Pose Coupling}\label{sec:fusion}

The two branches are coupled through the focal embedding: the calibration branch produces $\mathbf{K}$, the focal length is extracted and embedded, and this embedding conditions the pose head. During training, both branches are optimised jointly, so \textbf{improved calibration directly benefits pose estimation, and the pose loss provides gradient signal back to the calibration branch}.

\section{Instantiation with AnyCam and AnyCalib}\label{sec:instantiation}
% ============================================================================

The framework is demonstrated by fusing two complementary pretrained models: AnyCam~\parencite{wimbauer2025anycam}, a self-supervised pose estimator, and AnyCalib~\parencite{tirado2025anycalib}, a single-image calibration network.

\subsection{Calibration Branch: AnyCalib + MCT}\label{sec:calib-branch}

AnyCalib provides the calibration backbone and decoder:

\begin{enumerate}
    \item \textbf{Feature extraction.} A frozen DINOv2 ViT-L/14 backbone produces spatial features at four resolutions ($S=4$, $C=1024$) from transformer blocks 4, 11, 17, and 23.

    \item \textbf{MCT.} Configured with 8 attention heads ($d_{\text{head}} = 128$), FFN $1024 \to 4096 \to 1024$ with GELU, pre-layer normalisation. Weights shared across all four scales (${\sim}25$M parameters).

    \item \textbf{Decoding.} The frozen Light-DPT decoder (a lightweight CNN) and ray head (convex upsampling) produce per-pixel 3D rays $\mathbf{R} \in \mathbb{R}^{H \times W \times 3}$.

    \item \textbf{Calibration fitting.} A pinhole model is fit to the rays via RANSAC and least squares, yielding $(f_x, f_y, c_x, c_y)$. This step is non-differentiable.
\end{enumerate}

Without the MCT, these features would be decoded per-frame and the resulting scalar predictions averaged---a simple baseline that discards spatial structure. The MCT replaces this averaging with learned feature-level aggregation.

\subsection{Pose Branch: AnyCam}\label{sec:pose-branch}

AnyCam provides the pose backbone and prediction heads (Figure~\ref{fig:anycam-pipeline}):

\begin{itemize}
    \item A frozen DINOv2-small (ViT-S/14) backbone receives input frames concatenated with precomputed depth (UniDepth) and optical flow (UniMatch) as additional channels. It extracts CLS tokens from four transformer stages.

    \item A trainable \textbf{pose neck} (${\sim}2.5$M parameters) reassembles and fuses these tokens, then applies eight layers of multi-head self-attention across frames for multi-frame pose reasoning.

    \item A learned \textbf{focal embedding} (our addition) converts the predicted focal length from the calibration branch to an 8-dimensional harmonic encoding, concatenated with the pose tokens. This replaces AnyCam's original 32-candidate focal length selection system.

    \item A trainable \textbf{pose head} (${\sim}21$K parameters) maps each 136-dimensional token ($128 + 8$) to a 7-dimensional output: unit quaternion (4D) and translation direction (3D).
\end{itemize}

\subsection{Training Data}\label{sec:training-data}

Training uses four diverse video datasets: RealEstate10K~\parencite{zhou2018realestate10k} (indoor walkthroughs), YouTube VOS~\parencite{xu2018youtubevos} (diverse YouTube content), WalkingTours (urban walking), and OpenDV (driving). All data is preprocessed offline: optical flow (UniMatch), depth (UniDepth), and per-frame calibration (AnyCalib) are computed for all consecutive frame pairs.

\subsection{Multi-Frame Consistency via Flow Composition}\label{sec:flow-composition}

Training uses 4-frame windows ($\text{max\_ahead}=3$). Long-range flows are composed from consecutive flows through bilinear interpolation:
\begin{equation}
    \mathbf{w}_{1 \to 3}(u,v) = \mathbf{w}_{1 \to 2}(u,v) + \mathbf{w}_{2 \to 3}\bigl((u,v) + \mathbf{w}_{1 \to 2}(u,v)\bigr)
\end{equation}
This yields 5 training pairs (3~consecutive + 2~composed) from $O(N)$ flow computations. Preliminary experiments (Appendix~\ref{chapter:preliminary-results}) identified $\text{max\_ahead}=3$ as optimal.

\subsection{Loss Functions}\label{sec:losses}

In general terms, the framework requires two loss signals: a \textbf{self-supervised flow reprojection loss} as the primary training signal, and a \textbf{calibration anchor loss} that prevents calibration from drifting unconstrained. The specific formulations below arise from the AnyCam and AnyCalib instantiation.

\subsubsection{Flow Reprojection Loss (Main Signal)}

For each consecutive frame pair $(i, i{+}1)$, the predicted pose $(R, \mathbf{t})$ from AnyCam's pose head, precomputed depth $D^i$ from UniDepth, and predicted intrinsics $\mathbf{K}$ from the calibration branch are used to induce an optical flow field. Each pixel $\mathbf{x} = (u, v, 1)^\top$ in frame $i$ is unprojected to 3D, transformed by the predicted pose, and reprojected:
\begin{equation}
    \mathbf{x}' = \pi\!\left(\mathbf{K}\left(R\,\mathbf{K}^{-1} \mathbf{x}\, d + \mathbf{t}\right)\right)
\end{equation}
The induced flow $\hat{\mathbf{w}} = \mathbf{x}' - \mathbf{x}$ is compared against the observed flow $\mathbf{w}_\text{obs}$ precomputed by UniMatch. Following AnyCam, the per-pixel loss uses a Laplacian negative log-likelihood weighted by a learned uncertainty map $\sigma^i$ predicted by the pose branch:
\begin{equation}
    \mathcal{L}_{\text{flow}}^{(i \to i+1)} = -\frac{1}{|\Omega|} \sum_{\mathbf{x} \in \Omega} \ln \frac{1}{\sqrt{2}\,\sigma^i_\mathbf{x}} \exp\!\left(-\frac{\sqrt{2}\,\|\hat{\mathbf{w}}_\mathbf{x} - \mathbf{w}_{\text{obs},\mathbf{x}}\|_1}{\sigma^i_\mathbf{x}}\right)
\end{equation}
The uncertainty $\sigma$ learns to down-weight dynamic objects and occluded regions, making the loss robust to non-static content.

\subsubsection{Calibration Anchor Loss}

\textbf{For small camera displacements} ($R \approx I$, $\mathbf{t} \approx 0$), the reprojection equation simplifies: $\mathbf{K}^{-1}(d\,\mathbf{K}\mathbf{x}) \approx \mathbf{x}$. The intrinsic matrix cancels out, leaving the flow reprojection loss near zero regardless of $\mathbf{K}$. In casual video, many frame pairs exhibit small camera motion, yet dynamic objects produce large optical flow---making it difficult to filter these pairs by flow magnitude. Without an anchor, calibration can drift to arbitrary values during training.

The calibration anchor penalises deviations from a pseudo ground truth $\mathbf{K}_\text{pseudo}$:
\begin{equation}
    \mathcal{L}_\text{anchor} = \|\mathbf{K}_\text{pred} - \mathbf{K}_\text{pseudo}\|
\end{equation}

In our instantiation, $\mathbf{K}_\text{pseudo}$ is obtained by \textbf{averaging AnyCalib's per-frame predictions over the training sequence}. While this average lacks multi-frame context and is not a perfect calibration estimate, AnyCalib's single-frame predictions are already reasonably accurate (Figure~\ref{fig:calib-stability}), making their average an acceptable anchor target. The anchor serves two roles:
\begin{enumerate}
    \item During \textbf{Phase~B} (MCT pre-training), the anchor is the primary loss. The goal is to bring the MCT's output to at least the quality of per-frame averaging before introducing the complexity of joint training.
    \item During \textbf{Phase~C} (joint training), the anchor is retained but with a deliberately small weight ($\lambda_\text{calib} = 10^{-4}$). The averaged per-frame predictions are reasonable but not optimal; the model is therefore allowed to learn a better calibration through the flow reprojection signal from the pose branch, while being discouraged from diverging too far from the already-reasonable average.
\end{enumerate}

\subsubsection{Composed Flow Loss}

Multi-frame consistency is enforced by combining consecutive and composed flow pairs:
\begin{equation}
    \mathcal{L}_{\text{multi}} = \sum_{i=1}^{N-1} \mathcal{L}_{\text{flow}}^{(i \to i+1)} + \lambda_{\text{comp}} \sum_{j>i+1} \mathcal{L}_{\text{flow}}^{(i \to j)}
\end{equation}
where $\lambda_{\text{comp}} = 0.1$ down-weights composed pairs to account for error accumulation from bilinear interpolation.

\subsubsection{Pose Consistency Loss}

Forward-backward consistency ensures that composing a forward and backward pose prediction yields the identity: $\mathcal{L}_\text{consist} = \|P^{i \to j} \cdot P^{j \to i} - I_4\|$.

\subsubsection{Combined Loss per Phase}

\begin{itemize}
    \item \textbf{Phase A}: $\mathcal{L}_A = \mathcal{L}_{\text{multi}} + \mathcal{L}_\text{consist}$ \quad (pose head only; calibration is static per-frame average)
    \item \textbf{Phase B}: $\mathcal{L}_B = \mathcal{L}_\text{calib}$ \quad (MCT only; ray reprojection against pseudo GT, see below)
    \item \textbf{Phase C}: $\mathcal{L}_C = \mathcal{L}_{\text{multi}} + \mathcal{L}_\text{consist} + \lambda_\text{calib}\,\mathcal{L}_\text{anchor}$ \quad ($\lambda_\text{calib} = 10^{-4}$)
\end{itemize}

The Phase~B calibration loss bypasses the non-differentiable RANSAC calibrator by projecting MCT's predicted rays directly to image coordinates using pseudo ground truth calibration:
\begin{align}
    u^{\text{proj}} &= f_x \cdot \frac{R_x}{R_z} + c_x, \quad
    v^{\text{proj}} = f_y \cdot \frac{R_y}{R_z} + c_y \\
    \mathcal{L}_{\text{calib}} &= \frac{1}{HW} \sum_{p} \|(u^{\text{proj}}_p, v^{\text{proj}}_p) - (u_p, v_p)\|^2
\end{align}

\paragraph{Phase A: Pose head initialisation.} The pose head is fine-tuned using static calibration (AnyCalib per-frame predictions averaged over the sequence). This validates that the calibration network can replace the pose estimator's original calibration mechanism and provides a warm start.

\paragraph{Phase B: MCT pre-training.} Only the MCT is trained using $\mathcal{L}_\text{calib}$. The goal is to bring the MCT's output to at least the quality of per-frame averaging before exposing it to the complexity of joint training. This isolated initialisation prevents degenerate solutions.

\paragraph{Phase C: Joint training.} The pose neck, pose head, and MCT are trained jointly using $\mathcal{L}_C$. All pretrained backbones and decoders remain frozen---approximately 27.5M of 370M total parameters are trainable (7.5\%). The small calibration anchor weight ($\lambda_\text{calib} = 10^{-4}$) allows the model to learn calibration that optimises pose quality through the flow reprojection signal, while discouraging large deviations from the per-frame average which is already a reasonable estimate.
